# Dual-language outcomes

A longitudinal research dataset for dual-language programs across all **50 US states**, including all instructional languages. The national model separates school/program histories from three assessment layers: DL-participant reports, state assessments and context, and Stanford SEDA estimates.

**First structural research pass complete across all 50 states.** Partial programme evidence is integrated for **48 states**, including separately flagged candidates, historical hosts, continuations and later starts. **Mississippi and West Virginia have screening-only research**; no qualifying DL programme was verified in those passes, which is not a finding of statewide absence. All states retain discovery and verification gaps; the milestone is state coverage, not a complete school census. Existing assessment pilots are preserved. This structural pass adds no proficiency, demographic, EL-exit or SEDA observations.

**Native state-assessment collection now begins with EDC v3.1, spring 2022–2025.** The [school/grade dataset](data/assessments/edc_v3_1_2022_2025/README.md) retains ELA/math proficiency, achievement-category distributions and assessment-population subgroups. [School/year coverage](data/assessments/edc_v3_1_2022_2025/school_year_coverage.csv) records every baseline school, including gaps. Results remain on each state's scale; counts retain suppression and documented enrollment/older-year proxies. These are schoolwide results, not identified DL-participant outcomes.

## Install, build and validate

Python 3.10+ is supported. These commands use an isolated virtual environment:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-lock.txt -e .
.venv/bin/dl-outcomes validate
.venv/bin/dl-outcomes build
.venv/bin/python -m unittest discover -s tests -v
```

`build` is offline and deterministic for the saved input/config/code bytes. It creates all 28 contract tables, registers the separate partitioned EDC collection, produces structural review views and headers for uncollected layers, then validates them. `validate` checks source/report hashes, reporting grain, populations, identities, dates, attribution and the EDC collection manifest. `dl-outcomes edc check --reproduce` also recomputes every normalized EDC cell from the saved native rows. These checks do not independently verify every reported research claim.

The unchanged assessment pilots contain eight Texas subject results from four published one-way-DL/current-EL reporting groups, plus Washington school-level academic and enrollment observations for two multilingual elementary schools across 2023–24, 2024–25 and 2025–26. Washington program metadata covers a broader set of schools and preserves related heritage/tribal records for review. Program evidence groups are not verified distinct program counts.

## National baseline versions

The frozen structural baseline provides field-specific selections and missingness audits alongside the unchanged canonical histories. Its 2025–26 reference selections and the Texas 2023–24/Oregon 2026–27 source-vintage supplements are separate. Model notation, language ordering, grade scope, inference, conflicting sources and unknown applicability remain explicit.

The live research inventory and Fieldnotes exclude specialized deaf/blind education schools under the researcher’s [study-scope policy](config/study_scope.json). The [exclusion register](data/reports/hand_coding/current/study_scope_exclusions.csv) records the schools, reasons and supporting sources. Canonical source-history tables, original observations and frozen releases retain those identities for audit; use the current program-school cohort when joining archived assessment data. These exclusions describe research scope, not program closures or a filter on individual students’ disability status.

```bash
.venv/bin/dl-outcomes baseline check national_structural_v1 --reproduce
```

This recheck uses the baseline’s saved evidence and rules, so later live-data updates do not rewrite it. A new version can be created with `dl-outcomes baseline create NEW_ID --rules PATH_TO_NEW_RULES.json`; an existing ID is never overwritten. Normal validation checks registered baseline hashes, and portable research releases include the registered baselines. See the [dataset guide](data/baselines/national_structural_v1/README.md) for the CSV grains, exact source/code snapshot and historical reproduction command.

## Source collection and releases

The checked-in public snapshots and reviewed research inputs are sufficient to rebuild the dataset offline. A new acquisition must use a new vintage directory:

```bash
.venv/bin/dl-outcomes collect-wa-pilot
.venv/bin/dl-outcomes collect-wa-pilot --destination data/raw/wa/another_vintage
.venv/bin/dl-outcomes build
.venv/bin/dl-outcomes release my-reviewed-release
```

Cached snapshots are hash-checked and never overwritten. Changes to the configured query require a new vintage. A frozen release bundles the exact source inputs, configs, pipeline, contracts and curated outputs. The command creates a local artifact; it does not publish or push anything. Frozen release IDs cannot be reused.

For larger analytical extracts:

```bash
.venv/bin/python -m pip install -r requirements-analytics-lock.txt -e .
.venv/bin/dl-outcomes export-analytics --destination data/releases/analytics_v1
```

This exports separate typed Parquet tables and a DuckDB database. Keep large future source snapshots/bundles in versioned artifact storage and retain their manifests and checksums. Source vintages remain distinct: analyses must explicitly select releases and compatible definitions.

Earlier Texas and five-state checkpoints remain in their original locations. Their integrated records retain closures, future proposals, funding/content candidates, continuity reviews and source-specific design dates. California's historical CDE school leads and Oregon's related language-class listings remain screening evidence rather than extra confirmed programs. The five national seed CSVs have standardized headers and whitespace; their original bytes and migration checksums are in [the legacy snapshot](data/raw/legacy_registry/pre_schema_v1/manifest.json).
